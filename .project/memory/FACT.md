# FACT

> 持久知识，6个月内仍然重要的事实和决策。

## 边界规则

- **此仓库是用户的独立 agent 系统（类似 superpowers），未经用户明确要求，禁止修改此仓库的任何文件**
- **不再主动讨论智能体制作相关话题**，只有用户明确要求时才执行此项目的操作
- my.md 永远只读，make.md 及其他文件只在用户要求时才可修改

## 活跃项目

### Agent 协作工作流体系
- 设计文件：`my.md`（原始设计，不修改）、`make.md`（完善方案，持续维护）
- 核心架构：7 角色（用户、主Agent、批复角色、文档维护角色、实施角色、内容审查角色、测试角色）
- 工作流：4 阶段串行推进（需求讨论 → 任务规划 → 实施调度 → 总结报告）
- 文档体系：4 类文档（需求、进度、任务、实施经验），路径统一在 `/project/.project/`
- 记忆体系：5 类记忆（需求、进度、任务、纠错、报错），3 级优先级
- 批复角色模式：对抗型身份 + 流程驱动，统一执行流程为"提取→对照→产出"，融入 pua-skill 精华（穷尽一切、冰山法则、偷懒识别、压力升级L0-L4）
- 参考 skill：pua-skill (https://github.com/tanweai/pua)
- 实施路线：6 步落地计划（skill集成 → 文档模板 → 四阶段工作流 → 角色配置 → 记忆管理 → 整合测试）

## 技术决策
- 文档路径规范：`project/.project/` 目录下
- 大型项目支持按模块/里程碑拆分进度文档和任务文档
- 高频问题（3次+）自动提升至 FACT.md 持久保留
- 中文优先：所有文档、沟通、注释必须使用中文；英文报错必须附带中文翻译和可能原因
- 难题体系：5级难度（⭐~⭐⭐⭐⭐⭐），难题必须有突破计划（调研→POC→实施），连续2次未通过验收自动升级，瓶颈级必须向用户汇报
- 可视化优先：方案流程用ASCII流程图、任务体系用WBS、多角色协作用泳道图、架构用架构图、目录用树形图
- **核心设计原则1：抽象词必须拆解为可观测、可度量的具体标准**——AI 不理解"完整性""合理性"等抽象概念，必须给出：具体检查什么、怎么检查、通过/不通过的具体条件
- **核心设计原则2：批复角色采用流程驱动的绝对性观念**——不评判"好不好"（主观），只检查"流程走没走完、产出有没有"（客观）。每个批复项 = 先做A → 再做B → 产出C → C中有❌则不通过，无❌则通过。结论由流程产出决定，不由主观判断决定
- **核心设计原则3：批复角色是对抗型身份**——借鉴 pua-skill，批复角色必须对所有结论性内容产生专业型质疑：穷尽一切才可放行、冰山法则（发现一个追查同类）、识别偷懒模式（暴力重试/甩锅/工具闲置/磨洋工/被动等待/虚假完成）、压力升级L0-L4
