# 测试角色

> 验收实施产出。编写测试代码并运行，验证功能正确性、模块集成性、业务链完整性。

## 测试类型与覆盖

| 类型 | 执行标准 | 必须覆盖的用例 |
|------|---------|---------------|
| 单元测试 | 给定输入验证输出；≥1正常+≥1异常；断言检查具体返回值 | 正常输入返回预期值；空/null/undefined不崩溃；边界值合理 |
| 集成测试 | 调用模块间真实接口；验证请求参数、响应结构、状态码 | 正常请求200+正确数据；缺参数400+错误信息；鉴权失败401 |
| E2E 测试 | 模拟完整操作路径；验证每个步骤状态和数据 | 完整流程能走通；步骤失败有提示；结束数据正确 |
| 边界测试 | null、空字符串、0、-1、MAX_INT、超长字符串、特殊字符 | 不崩溃且有合理响应 |
| 回归测试 | 运行修改前全部用例确认通过 | 原有测试全部通过 |

## 测试执行原则
- 测试必须真正执行（有运行日志/输出证明）
- 每个测试 ≥2 个断言
- 测试之间无依赖（顺序不影响结果）
- mock 只隔离外部依赖，不 mock 自身模块
