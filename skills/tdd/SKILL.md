# 测试驱动开发（TDD）

> 先写测试，再看它失败，再写最少代码让它通过，最后在测试保护下重构。

## 核心铁律

```
没有先看到测试失败 → 就没资格写实现代码。
写了实现代码但没测试 → 删掉重来。
```

## 红-绿-重构循环

```
┌─ RED ───────────────────────────────────────────┐
│  写一个会失败的测试 → 验证它确实失败               │
│  (证明测试有效，测试的是新功能而非已有代码)          │
└─────────────────────┬───────────────────────────┘
                      ▼
┌─ GREEN ──────────────────────────────────────────┐
│  写最少量的代码让测试通过                          │
│  (不做过度设计，不写测试没覆盖到的代码)              │
└─────────────────────┬───────────────────────────┘
                      ▼
┌─ REFACTOR ───────────────────────────────────────┐
│  在测试保护下优化代码结构                           │
│  (改完后测试依然全绿，证明没破坏功能)                │
└─────────────────────┬───────────────────────────┘
                      ▼
                  下一个 RED...
```

### RED — 写失败测试

写一个最小测试，描述应该发生的行为。

**要求：**
- 一个测试只验证一个行为（测试名中有"and"就拆开）
- 测试名清晰描述行为（不是 test1/test2）
- 使用真实代码逻辑（非迫不得已不用 mock）
- 测试的是行为，不是实现细节

### 验证 RED — 看它确实失败

**必须执行，不准跳过。**

```bash
npm test path/to/test.test.ts
```

确认：
- 测试确实失败（不是报错）
- 失败原因是功能缺失（不是拼写错误）
- 测试立即通过了？那你在测已有功能。修正测试。

### GREEN — 最小实现

写刚好能让测试通过的代码。

**不要：**
- 添加测试没覆盖的功能（YAGNI）
- 优化还没测试的代码
- 提取抽象层
- 添加配置项

### 验证 GREEN — 看它通过

```bash
npm test path/to/test.test.ts
```

确认：
- 测试通过
- 其他测试依然通过
- 输出干净（无报错/警告）

### REFACTOR — 优化

**只在 GREEN 后执行：**
- 删除重复
- 改善命名
- 提取辅助函数
- 保持测试全绿
- 不添加新行为

## 常见借口与事实

| 借口 | 事实 |
|------|------|
| "这太简单了不需要测试" | 简单代码也会坏。写个测试只要 30 秒。 |
| "我之后再补测试" | 之后补的测试一次就通过，证明不了什么。 |
| "我已经手动验证过了" | 手动验证不是系统的。没有记录、不能重跑。 |
| "先写代码再做 TDD 一样" | 代码先写 = 测试被实现影响。你测的是你写的，不是要求的。 |
| "删掉 X 小时的工作太浪费" | 沉没成本谬误。留着不能信任的代码才是真正的浪费。 |
| "TDD 太教条了" | 先测再写比调试快十倍。教条的是"没测试就敢上线"。 |
| "我先探索一下，之后补" | 探索可以。探索完删掉重来 TDD。 |

## TDD 与 skeptics 三层验证的关系

```
TDD (Worker Subagent)     →  单元级，保证"代码做对了"
Tester (独立 Subagent)    →  集成/E2E/边界，保证"系统能用了"
Reviewer (Skill)          →  规范/设计/安全，保证"代码能维护了"

三层互不替代，互为补充。
TDD 是开发方法论，Tester 是独立验证，Reviewer 是质量审查。
```

## 验证清单

实施完成前检查：

- [ ] 每个新函数/方法都有测试
- [ ] 每个测试都亲眼看过它失败（在实现之前）
- [ ] 每个测试失败的原因都是"功能缺失"（不是拼写错误）
- [ ] 写了最少代码让每个测试通过
- [ ] 所有测试通过（无失败、无报错、无警告）
- [ ] 测试使用真实代码（mock 只在迫不得已时用）
- [ ] 边界情况和错误路径已覆盖
- [ ] 重构后测试依然全绿

不能勾选全部 → 没有真正执行 TDD → 从头开始重做。
