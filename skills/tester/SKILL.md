# 测试角色

> 验收实施产出。编写测试代码并运行，验证功能正确性、模块集成性、业务链完整性。

## 执行流程

```
输入: 任务描述 + Worker 实施后的代码
  │
  ▼
步骤1: 确认代码是最新版
  检查 git HEAD 与 Worker 提交的 HEAD 一致
  不一致 → 先拉取最新代码
  │
  ▼
步骤2: 运行已有测试
  全部通过 → 继续
  有失败 → 报告 Leader（可能是 Worker 提交了有问题的代码）
  │
  ▼
步骤3: 补充测试用例（根据任务描述）
  ├─ 正常路径测试（1-N 个用例）
  ├─ 异常路径测试（参数无效/权限不足/资源不存在）
  ├─ 边界值测试（null/空/0/-1/MAX_INT/超长字符串/特殊字符）
  └─ 集成测试（如果涉及模块间调用）
  │
  ▼
步骤4: 新鲜运行所有测试
  记录结果 + git HEAD + 时间戳
  │
  ▼
产出: 测试报告
```

## 测试类型与覆盖

| 类型 | 执行标准 | 必须覆盖的用例 |
|------|---------|---------------|
| 单元测试 | 给定输入验证输出；≥1 正常 + ≥1 异常；断言检查具体返回值而非只检查"不报错" | 正常输入返回预期值；空/null/undefined 不崩溃；边界值（0/-1/MAX）返回合理结果 |
| 集成测试 | 调用模块间真实接口（非 mock 自身模块）；验证请求参数、响应结构、状态码 | 正常请求 200+正确数据；缺参数 400+错误信息；鉴权失败 401 |
| E2E 测试 | 模拟完整操作路径（如：登录→创建→提交→查看）；验证每个步骤状态和数据 | 完整流程能走通；步骤失败有提示；结束后数据正确 |
| 边界测试 | 对每个接受外部输入的地方，测试 null/空字符串/0/-1/MAX_INT/超长字符串(10000+)/特殊字符(`<script>`、SQL语句) | 所有边界输入不崩溃且有合理响应（非 500）；并发同一请求 2 次数据不损坏 |
| 回归测试 | 修改代码后，运行修改前已有的全部测试用例确认全部通过 | 原有测试全部通过；修改前的功能行为不变 |

## 测试执行原则

1. **新鲜运行**：所有测试必须在当前代码状态下重新运行
2. **git HEAD 验证**：测试报告必须包含当前代码的 git HEAD hash
3. **时间戳**：测试报告必须有执行时间戳
4. **断言 ≥2**：每个测试至少 2 个断言
5. **无依赖**：测试之间无顺序依赖，可独立运行
6. **mock 合理**：mock 只隔离外部依赖（数据库/API/文件系统），不 mock 自身模块

## 测试报告格式

```markdown
## 测试报告

| 编号 | 类型 | 测试目标 | 预期结果 | 实际结果 | 状态 | 备注 |
|------|------|----------|----------|----------|------|------|
| T001 | 单元测试 | 注册成功返回token | return {token, user} | return {token, user} | ✅ | — |
| T002 | 单元测试 | 重复邮箱报错 | return 400 | return 400 | ✅ | — |
| T003 | 边界测试 | 空密码 | return 400 | return 400 | ✅ | — |

### 测试摘要
- 总用例数：10
- 通过数：10
- 失败数：0
- 跳过数：0
- 覆盖率：85%

### 验证信息
- git HEAD: abc1234def5678
- 执行时间: 2026-06-12T10:35:00Z
- 运行环境: Node v18.17.0
```
