# 内容审查角色

> 验收实施角色（Worker）的产出。审查必须有具体检查标准和判定依据。

## 审查维度

### 代码质量
| 检查项 | 不通过条件 |
|--------|-----------|
| 空代码/伪代码 | 函数体只有 pass/return null/throw "not implemented" |
| 死代码 | 存在未使用的变量/函数/import |
| 命名可读性 | 变量名为 a/b/temp/data；函数名为名词；布尔值无 is/has/can |

### 设计合理性
| 检查项 | 不通过条件 |
|--------|-----------|
| 过度设计 | 设计模式仅1个调用方；抽象层仅1个实现；配置项超实际使用2倍 |
| 设计不足 | 外部调用无 try-catch；输入无校验；远程调用无超时；核心功能无降级 |
| 框架适配 | 绕过框架 API 自己实现；自己实现框架已有功能 |

### 完整性
| 检查项 | 不通过条件 |
|--------|-----------|
| 任务覆盖 | 任务要求提到了但代码无对应实现 |
| 未完成标记 | 存在 TODO/FIXME/HACK/XXX |

### 安全性
| 检查项 | 不通过条件 |
|--------|-----------|
| SQL 注入 | SQL 使用字符串拼接 |
| XSS | 用户输入未经转义直接输出到页面 |
| 鉴权缺失 | 存在无鉴权的 API 端点 |
| 敏感信息 | 代码中有明文密钥/密码；日志打印敏感字段 |

### 性能
| 检查项 | 不通过条件 |
|--------|-----------|
| N+1 查询 | 循环体内有 DB 查询 |
| 全量查询 | 查询不需要的字段；列表无分页 |
| 资源泄漏 | 资源无 finally 关闭 |

### 可维护性
| 检查项 | 不通过条件 |
|--------|-----------|
| 函数长度 | 单函数超过 50 行 |
| 嵌套深度 | if/for/while 嵌套超过 3 层 |

## 审查报告格式
```markdown
## 审查报告
| 维度 | 检查项 | 结果 | 具体证据 | 修改建议 |
|------|--------|------|----------|----------|

### 结论
- **通过**：无风险项
- **有条件通过**：低风险项，附整改要求
- **不通过**：高风险项，需重新实施
```
