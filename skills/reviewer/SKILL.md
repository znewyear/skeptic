# 内容审查角色

> 审查必须有具体检查标准和判定依据。每个检查项的结果必须有证据支持。

## 审查流程

```
输入: Worker 实施结果（git diff + 测试报告 + 任务描述）
  │
  ▼
逐项执行检查清单
  │
  ▼
汇总 verdict
  ├─ PASS → 进入下一环节
  ├─ CONDITIONAL_PASS → 低风险问题，附整改要求
  └─ FAIL → 附所有 issues，返回 Worker 修复
```

## 审查维度

### 代码质量

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| 空代码/伪代码 | 函数体只有 pass/return null/throw "not implemented" | 阅读函数体 |
| 死代码 | 存在未使用的变量/函数/import | 搜索引用点 |
| 命名可读性 | 变量名为 a/b/temp/data；函数名为名词；布尔值无 is/has/can | 阅读命名 |

### 设计合理性

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| 过度设计 | 设计模式仅1个调用方；抽象层仅1个实现；配置项超实际使用2倍 | 计数调用方/实现类 |
| 设计不足 | 外部调用无 try-catch；输入无校验；远程调用无超时；核心功能无降级 | 逐项检查防护措施 |
| 框架适配 | 绕过框架 API 自己实现；自己实现框架已有功能 | 与官方文档对照 |

### 完整性

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| 任务覆盖 | 任务要求提到了但代码无对应实现 | 逐条对照任务描述和代码 |
| 超过范围 | 实现了任务未要求的功能且未说明 | 检查是否有非任务要求的代码 |
| 未完成标记 | 存在 TODO/FIXME/HACK/XXX/TEMP | grep 搜索 |

### 安全性

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| SQL 注入 | SQL 使用字符串拼接 | 检查 SQL 语句构造方式 |
| XSS | 用户输入未经转义直接输出到页面 | 检查渲染方式 |
| 鉴权缺失 | 存在无鉴权的 API 端点 | 逐端点检查是否有鉴权中间件 |
| 敏感信息 | 代码中有明文密钥/密码/token；日志打印敏感字段 | grep 搜索密钥模式 |
| 上传安全 | 上传无类型白名单、无大小限制 | 检查上传处理代码 |

### 性能

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| N+1 查询 | 循环体内有 DB 查询 | 检查循环内是否有 DB 调用 |
| 全量查询 | 查询不需要的字段（SELECT *）；列表无分页 | 检查查询语句 |
| 资源泄漏 | 资源（连接/文件/流）无 finally/async 关闭 | 检查资源清理代码 |
| 大数据量 | 一次性加载全部数据到内存；无分批处理 | 检查是否有分页/流式处理 |

### 可维护性

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| 函数长度 | 单函数超过 50 行（不含空行和注释） | 行数统计 |
| 嵌套深度 | if/for/while 嵌套超过 3 层 | 阅读嵌套结构 |
| 注释缺失 | 复杂逻辑（3行以上非直白操作）无说明；公共 API 无文档注释；魔法数字无含义说明 | 阅读关键代码块 |

### 一致性

| 检查项 | 不通过条件 | 检查方法 |
|--------|-----------|---------|
| 代码风格 | 新代码命名风格/缩进/引号/分号与项目不一致 | 与项目已有代码对照 |
| 技术约束 | 使用的技术栈/依赖版本超出需求文档中的约束 | 与 requirement.md 对照 |

## 审查报告格式

```markdown
## 审查报告

| 维度 | 检查项 | 结果 | 具体证据 | 修改建议 |
|------|--------|------|----------|----------|
| 代码质量 | 空代码 | ✅ | — | — |
| 安全性 | SQL注入 | ❌ | src/user.ts:45 SQL字符串拼接 | 改为参数化查询 |
| 性能 | N+1查询 | ❌ | src/order.ts:78 循环内查DB | 加 JOIN 一次查完 |

### 结论
- **PASS**：无风险项
- **CONDITIONAL_PASS**：低风险项，附整改要求
- **FAIL**：高风险项，需重新实施

审查时间: ISO时间戳
git HEAD: abc1234
```
